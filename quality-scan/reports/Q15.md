## Q15-01 — P2 HIGH — the error-tracking suite certifies "no PII" from a deprecated kwarg while the pinned SDK still ships request bodies and frame locals (CODE, Confidence H)

**Where**: `backend/tests/test_error_tracking.py:421-424` (`test_pii_is_never_sent_by_default`), `:282-283` (`assertIn("PII False", ...)`), `backend/tests/test_sentry.py:196`; the pinned behaviour is in `venv/Lib/site-packages/sentry_sdk/data_collection.py:153-188` and `integrations/_wsgi_common.py:96-135`.

**Invariant asserted vs invariant held**: "request bodies, cookies and identifiers stay inside the process" (`common/sentry.py:426-428` comment, `test_error_tracking.py:422-423` docstring). Cookies, headers and query params are indeed filtered (`_SENSITIVE_DENYLIST`). Bodies and stack-frame variables are not.

**Evidence (measured, not inferred)**: options dump above from the installed `sentry_sdk.VERSION == 2.71.0`, which is exactly the pin at `requirements.lock:1033` and is proven installed by `test_error_tracking.py:370-388`. `data_collection.py:175-177` and `:307-311` are the two defaults that decide it; `_wsgi_common.py:126-135` is where the body reaches the event.

**Why the tests miss it**: `send_default_pii` is the only PII lever the repo knows about, and it is now mapped through `_map_from_send_default_pii` into the structured `data_collection` option — a mapping that deliberately keeps the historical body behaviour. The suite asserts the input to that mapping, so it will keep passing through any SDK upgrade that changes the output.

**Fix direction**: set `data_collection` explicitly (`http_bodies: []`, `stack_frame_variables: False`), `max_request_body_size="never"`, and add one assertion on the captured envelope from `RecordingTransport` (`test_sentry.py:586-594`) that a request-scoped event carries no `request.data`, no `user`, no frame vars. Cross-reference: QC-025 (the absent scrubber); this row is the certification, not the mechanism.
