## Axis 1 — invariants, and whether they are enforced (not intended)

1. **Bearer must not be CSRF-gated; session-cookie mutations must be.** *Enforced.* `DEFAULT_AUTHENTICATION_CLASSES` is
   `(JWTAuthentication, SessionCartCSRFAuthentication)` (`settings.py:1261-1271`) and DRF's chain stops at the first
   authenticator that returns, so a bearer request never reaches the gate. Pinned by `tests/test_csrf_security.py:57`
   (wiring) and `cart/test_csrf.py:209-231` (behaviour: login → session cart → checkout 201 with no CSRF header).
2. **Anonymous session-cookie mutations must be rejected without a token.** *Enforced.* `authentication.py:49-57` calls
   `enforce_csrf`; `cart/test_csrf.py:66-129` proves POST/PATCH/DELETE 403 **and** that no `CartItem` was written
   (`:76`) — the guard is mutation-proven: delete `:49-57` and those tests go 201/200/200.
3. **Django-session-authenticated mutations must be rejected without a token.** *Enforced* (`:44-48`, test `:171-195`).
4. **A fresh visitor's first mutation is exempt.** *Enforced by design and pinned* (`cart/test_csrf.py:157-169`) — see Q36-08.
5. **`quantize_money` is the single rounding authority, 2 dp, no float.** *Half-enforced.* 2 dp and Decimal are
   consistent (`money.py:13-24`), but the authority is not universal (Q36-06) and its contract is untestable as written (Q36-05).
   **No float reaches the wire**: `orders/serializers.py:18` renders `f"{quantize_money(value):f}"`.
   The `ROUND_HALF_EVEN` choice is *correct*, not a defect — Django's adapter does
   `value.quantize(Decimal(1).scaleb(-decimal_places), context=...)` (`venv/…/django/db/backends/utils.py:315-332`), which
   inherits the default context's HALF_EVEN, so in-memory and stored values agree. **There is no repo rule mandating
   HALF_UP** (`docs/conventions.md:15` mandates "always quantize", never a mode). Do not "fix" this to HALF_UP.
6. **One drain pass is bounded and never busy-loops on an empty outbox.** *Enforced and measured.*
   `notifications.py:1095-1098` breaks the moment a claim returns `None`; `tests/test_notification_outbox_worker.py:221`
   pins an idle pass at `assertNumQueries(1)`; batch bounds at `:1245-1262`; `--batch-size 0/-3/many` refused
   (`:1650-1668`) — `positive_int` (`:55-83`) is a real guard, not decoration (0 previously fell through `or` to a full pass).
7. **A side-effectful flow must be `transaction.atomic` + `select_for_update`.** The claim is (`notifications.py:822-837`),
   and the lock is pinned even on SQLite via an ORM-call spy (`tests/…:780-804`). The *send* is deliberately outside the
   transaction — correct — but the settle writes are unpredicated (Q36-01).
8. **No import-time side effects.** `commands/__init__.py` is empty; `money.py` and `authentication.py` import only stdlib/Django;
   `qr.py` imports `segno` and defines constants (Q36-07).

## Axis 2 — correctness (what I checked and found clean)

* **Bounded batch, stop-early, no sleep**: verified above. `now` is passed through per pass; descending order is
  `order_by("created_at", "pk")` (`notifications.py:762`) — deterministic, no pagination here to order wrongly.
* **`update_fields` discipline**: claim writes `attempts`, `next_attempt_at` only (`:836`); `_record_*`/`_dead_letter` are
  `QuerySet.update()` on purpose, and the reason (a `save()` would re-INSERT a purged row) is correct and documented (`:866-871`).
* **Partial failure mid-loop**: one row's exception is contained (`_deliver` catches everything except DB faults at
  `notifications.py:1060-1069`), pinned with the poison row *in the middle* of a batch (`tests/…:487`). A DB fault is
  deliberately not swallowed (`:1037-1040`), which is the right call, but see Q36-03: the pass then dies with no summary line.
* **`positive_int`**: `int()` on a non-numeric → `ArgumentTypeError` naming the option; `< 1` refused; not capped (a huge
  `--batch-size` is an operator's own ceiling — acceptable, not a finding).
* **Timezone**: every comparison is `timezone.now()`-based, one clock source; no naive datetimes in this flow.
* **`qr_data_uri`**: pure function of its argument, returns a `data:` URI; base64 cannot break the JSON or an `<img src>`
  context and the scheme pins the type (`qr.py:42,56`). `xmldecl=False` keeps the payload valid inline.

## Axis 3 — SAST

No `permission_classes` surface in three of these five files (they are not views). The gate is the authz artifact and it
fails closed for every request that carries the cookie. No secrets, no logs of secrets (`_error_text` is bounded to 500
chars and typed, `notifications.py:1012-1023`), no raw SQL, no deserialization, no SSRF, no PII to third parties in these
files (the QR payload is an `otpauth://` URI containing the user's *own* secret, returned once to the authenticated
enroller — `accounts/views.py:948-955`). Unbounded-query candidates: the peek is sliced by `limit` (`:809`), the status
report is one `GROUP BY` (`:1114`), but `retry_dead_notifications` is one unbounded `UPDATE` over every DEAD row
(`notifications.py:1194-1197`) — on a poison-template incident that is a single long write; noted, not raised above the
P3 fold-in because the row count is bounded by the dead-letter population.

## Axis 4 — architecture / smells

* `common/authentication.py` is a **pure gate that returns `None`**: DRF identity is unchanged for session requests. This is
  *correct today* (JWT is the only credential in the chain) but the docstring's "a session-authenticated request keeps
  resolving to the same DRF identity it had before this class existed" (`:36-39`) is true only because nothing in DRF ever
  used session auth — a Django-`login()`-ed user *is* `AnonymousUser` at the DRF layer through this chain. Worth a
  one-line comment, not a row.
* Command layering is clean: argparse validation → `common.notifications` (the loop) → `common.models`. No DB query in the command.
* `money.py` lives in `common` (shared kernel) and is imported by `settings.py:34` — correct (pure stdlib, no app registry).
* Duplication: Q36-06. Dead code: none found. Naming vs `conventions.md`: consistent (no `is_staff` inline, no `'__all__'`,
  Decimal everywhere).
