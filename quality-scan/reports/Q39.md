## Findings

### Q39-01 | P3 LOW | TEST | `orders/tests.py:4940-4954` (predicate `orders/views/checkout.py:733`) | Confidence H — FOLD-INTO-NEXT

**Claim.** The flag is never proven sufficient on its own: the class's only **single-line** flagged cart (`4941`) also carries a `free_shipping` coupon that zeroes the charge independently, so the coupon — not the flag — satisfies the assertion. The one test that genuinely depends on the flag (`4909`) uses a **mixed** cart. The primary real-world case (a merchant flags one perfume; the customer buys that perfume alone) is therefore covered only in combination.

**Evidence.**
- `checkout.py:733-737` — `free_delivery = any(item.product.free_shipping for item in cart_items) or (coupon is not None and coupon.discount_type == Coupon.FREE_SHIPPING)`; `if free_delivery: shipping_amount = Decimal("0.00")`. Two disjuncts, one effect.
- `4941` seeds `[(self.flagged, 2)]` and `4943` posts `coupon_code="FREESHIP"`. Delete the `any(...)` disjunct and this test still gets `shipping_amount == 0.00` (`4948`) and `total_amount == 500.00` (`4952`) from the coupon's disjunct — **it stays green.** `4954` (`shipping_method_code == "standard"`) also stays green, because the quote still runs.
- The class's `setUp` creates `self.charged` and `self.flagged` but no test seeds `[(self.flagged, n)]` **without** a coupon. A predicate narrowed to multi-line carts (`len(cart_items) > 1 and any(...)`) passes all four tests: `4909` has 2 lines, `4930` has no flag, `4941` is rescued by the coupon, `4963` is refused before pricing.
- That narrowing is **not** caught anywhere else: `grep free_shipping` over `backend/**.py` → the only other checkout waiver pins are `shipping/tests.py:559` (coupon), `:576` (coupon + unserviceable), `531` (threshold); no other test sets `free_shipping=True` on a product (`products/tests.py:1269-1314` covers the column and the admin only). So the surviving-mutation set is exactly one: *single-line carts don't qualify*.
- What **is** proven, and it is worth recording so it is not re-litigated: `any`→`all` fails `4909` (charged line would keep 49.00 and total 1049.00) — the mutation the builder claimed at `docs/run/BUILD-QUEUE.md:252` is genuinely proven; deleting the whole block fails `4909`; computing `total_amount` before the zeroing fails `4919`; skipping the quote for a waived order fails `4956-4970`.

**Impact.** A regression that makes the flag inert for single-item carts — the commonest cart on a perfume store — ships green. Fix is one 10-line test: `seed_session_cart([(self.flagged, 1)])`, `checkout(shipping_method="standard")`, assert `order.shipping_amount == 0.00`, `res.data["shipping_amount"] == "0.00"`, `order.total_amount == Decimal("250.00")`, `order.shipping_method == self.standard`, and `order.coupon is None`.

### Q39-02 | P3 LOW | TEST | `orders/tests.py:4917` (with `4919`, `4922`) | Confidence H (mechanism) / M (impact) — FOLD-INTO-NEXT

**Claim.** The class asserts the waived money on `res.data`, never on the rendered body, and never asserts `total_amount` on the wire at all — while the third bullet of the SPEC-C-03/04 changelog row claims the pin covers "order, **wire string** and audit trail" (`docs/changes.md:1940`).

**Evidence.**
- `4917` — `self.assertEqual(res.data["shipping_amount"], "0.00")`. `res.data` is `OrderSerializer(order).data` (`checkout.py:167-176`), i.e. pre-render `ReturnDict`. This module states the rule it is breaking, in its own file: *"``.data`` alone cannot prove this: DRF's JSON renderer is where a bare ``Decimal`` becomes a float, so each pin renders the response and reads the bytes/parsed body a client would actually receive"* (`488-490`), with the `_rendered`/`_wire` helpers at `494-506`.
- `total_amount` (`4919`) and `shipping_method_code` (`4922`) are asserted only against the ORM; no line in `4878-4971` touches `res.content` / `res.render()` / `json.loads`.
- Mitigation, stated for fairness: `MoneyWireFormatTests.test_checkout_money_is_two_decimal_strings_on_the_wire` (`550-567`) pins rendered `shipping_amount == "0.00"` **and** `total_amount == "900.00"` as 2-dp strings, with the serializer boundary proven both ways (`583-589`). But that fixture has no shipping method configured, so its `0.00` is the *no-shipping-configured* zero (`checkout.py:750-766`) — the waived-with-a-method shape (`shipping "0.00"` **and** `total "1000.00"` in the same body) is on the wire nowhere.
- Note the same weakness in the sibling delist pin (`products/test_delist.py:173-179`), so this is a house pattern, not a slip unique to this class.

**Impact.** A renderer-level regression in `OrderSerializer`'s money fields would be caught by `550`; a regression specific to the waived path — the shape in which `0.00` must coexist with a non-null method and a full-price total — is not. Fix: reuse `MoneyWireFormatTests._rendered` in `4909` and assert `'"shipping_amount":"0.00"'` plus `'"total_amount":"1000.00"'` in the body text.

### Q39-04 | P4 INFO | TEST | `orders/tests.py:4923-4927` | Confidence H — FOLD-INTO-NEXT

**Claim.** The audit-trail assertions are a second read of the same variables already asserted on the order row, so they read as independent witnesses but cannot fail independently.

**Evidence.** `checkout.py:889-907` writes `detail["shipping_amount"] = str(shipping_amount)` and `detail["shipping_method"] = shipping_quote.method_code` — the same `shipping_amount` local persisted at `:796` and the same quote the FK/code snapshot comes from at `:738-749`. ### Q39-05 | P4 INFO | TEST | `orders/tests.py:4950-4952` (+ docstring `4884-4886`) | Confidence H — FOLD-INTO-NEXT

**Claim.** The "One waiver, not two" pin asserts a property the implementation cannot violate: `shipping_amount` is assigned `Decimal("0.00")` exactly once, so applying both waivers is idempotent by construction and no double-effect is representable.

**Evidence.** `checkout.py:733-737` — the disjunction is evaluated, then a **single** assignment sets the amount; `total_amount = quantize_money(merchandise_total + shipping_amount)` at `:767` reads it once. There is no per-waiver subtraction that could be applied twice. Hence `4952` (`total_amount == 500.00`) is a tautology *for its stated reason* — it would still pass if the coupon disjunct were deleted (which is precisely Q39-01's point) and it cannot detect a "double effect" that the code shape forbids. It does carry real value as the convergence arithmetic pin (`discount_amount == 0.00` at `4949` + `coupon == self.freeship` at `4947` prove the free-shipping coupon attaches without discounting merchandise — the F-11 property), so this is a wording finding, not a request to delete the test.

**Impact.** A future refactor that *does* introduce stacked subtraction (e.g. `shipping_amount -= rate` per waiver) would be caught by `4916`/`4952` anyway; only the docstring's claim ("without a second effect") overstates what the assertion proves.

## Axis coverage

- *Authz* — the class runs authenticated (`4890-4892`) and asserts nothing about the anonymous path (deliberately: guest refusal lives at `4862-4874`). Correctly out of scope.

**CORRECTNESS (axis 2).** The class's arithmetic is exactly right and independently re-derived here: `500.00 + 2×250.00 = 1000.00` with delivery waived (`4918-4919`); `2×500.00 + 49.00 = 1049.00` (`4937`); `2×250.00 = 500.00` with coupon + flag (`4952`); `250.00` merchandise for the refused cart, nothing written (`4971`). Status codes are 201/201/201/400 and every one is asserted with `res.data` as the failure message, so a red run is diagnosable. No swallowed exception: `4956-4970` proves the `ShippingUnavailable` path (`checkout.py:909-917`) propagates out of the atomic block and leaves no order. No check-then-act, no `update_fields`, no timezone, no pagination in scope. One value-level observation that is a *code* property, not a test defect: the waiver reads the **live** `Product.free_shipping` (`:733`), so a merchant flipping the flag between add-to-cart and checkout changes the charge — no snapshot is taken, and no test could distinguish it from the desired behaviour; handed off, not reported.

**SAST (axis 3).** N/A by construction (test module), with the one thing tests can leak checked: fixtures use `make_user`/`api_login` defaults (`common/testing.py:173`), no real secret, no network (`razorpay_mock` unused here; no gateway call in the class), no PII beyond the shared `checkout_payload` constants, and `ruff` clean.

**ARCHITECTURE / SMELLS (axis 4).** The class extends `ApiTestCase` rather than `OrderTestBase` — correct, because it must control its own shipping fixture (`4903-4904`) and cart contents, and it still reuses the shared `make_product`/`seed_session_cart`/`checkout` helpers (`common/testing.py:106-295`) instead of open-coding requests, which keeps it aligned with the house style. No module-level side effects. The docstring (`4879-4887`) is accurate about the mechanism (waives the charge, not the service; quoted method retained; any-line; convergence) and is the best documentation of this predicate anywhere — better than the `checkout.py` comment, which does not mention the single-line case either.

**TEST SIDE (axis 5).** Would the tests fail if the guard were deleted? **Yes except for the single-line case** — deleting the whole waiver, deleting `any(...)`, flipping to `all(...)`, zeroing after `total_amount` is computed, and skipping the quote are each caught by `4909`/`4956`. Of the 22 measured assertions, 11 are `assertEqual` on persisted money or structure, 2 on the wire-adjacent `.data`, 1 on the 400 string, and the rest are the status/message preconditions — there is no `assertTrue(True)`-class vacuity. Isolation: every fixture row is created in `setUp`; no cross-class state, no `override_settings` leaking (`SHIPPING_FREE_THRESHOLD` is untouched here, so the class runs at the env default and the 49.00 rate is charged by `_charge`, `shipping/pricing.py:198-215`); no `skip`/`xfail`; no unbounded mock (zero mocks). Missing cases, in priority order: (1) single flagged line without a coupon — Q39-01; (2) the waived shape on the rendered wire — Q39-02; (3) flagged line + a **percentage** coupon (does the flag still waive while `discount_amount` applies, and does `total` equal discounted merchandise?), which the class cannot answer today — the coupon half of the disjunction is tested only for the free-shipping type at `4940`, while `shipping/tests.py:516-529` proves a percentage coupon *keeps* the charge when no flag is present; (4) flagged line + `SHIPPING_FREE_THRESHOLD` set (both waivers land on one amount), covered for the threshold alone at `shipping/tests.py:531-539`.
