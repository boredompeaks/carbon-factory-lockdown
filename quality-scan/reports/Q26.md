## Axis 2 — correctness of the tests themselves

- No tautological equality in the two strongest modules: both compare against an independently produced control (`_same_as_empty_object` computes the `{}` verdict first) and against the persisted row, not the echoed payload.
- `test_nonobject_bodies_accounts` sends raw strings for a stated and correct reason (`:21-24`: `format="json"` collapses falsy payloads to an empty body) and clears the cache per request so a 429 cannot impersonate a body verdict (`:55-61`) — this is the correct pattern; Q26-05 is the one site it forgot.
- `test_e2e_concurrency.py:102-107` uses `.stock_reservations.get()` with no filter; it holds today because each order carries exactly one hold. If the `IntegrityError` re-arm path (`_mint_order_reservations`) ever leaves two holds on one order, this raises `MultipleObjectsReturned` — an error, not a red, on a test whose subject is the reservation book.
- No `skip`/`expectedFailure`/`xfail` pins in any of the eight modules (grep), no network, no `manage.py`, no real credentials (`common/testing.py:34-35`).
- Global-scope assertions (`Order.objects.count() == 2`, `StockMovement.objects.count()`, `RestockNotification…count()`) are safe here only because every class is `TestCase`-rolled-back; they would become order-dependent under a `TransactionTestCase` conversion (which Q26-04's fix would require).
