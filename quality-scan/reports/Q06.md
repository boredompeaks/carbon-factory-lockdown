## Findings

### Q06-01 | P2 HIGH | CODE | `common/sentry.py:418-440` (with `304-343`) | Confidence H — NEXT-BUILD

**Claim.** The module promises a reporting shape with "no PII" and pins `send_default_pii: False`, but it never disables frame-local capture and never supplies a scrubbing `before_send`; the only `before_send` is the quota guard, which returns the event untouched. The SDK's built-in `EventScrubber` is exact-key and non-recursive, so secret-shaped local names and any nested payload reach the operator's Sentry org in plaintext.

**Evidence.**
- `sentrypy:304-343`: `before_send` inspects type/path, marks a dedupe key, bumps two counters, `return event`. It never touches `event["exception"]["values"][*]["stacktrace"]["frames"][*]["vars"]`, `event["request"]["data"]`, `event["request"]["headers"]` or `event["extra"]`; it never returns a redacted copy.
- `sentry.py:418-440`: no `include_local_variables`, no `max_request_body_size`, no `data_collection`, no `send_default_pii` on frames. SDK `consts.py:1351` — `include_local_variables: Optional[bool] = True` is the default that applies. `attach_stacktrace: False` (line 434) is a *different* option and does not disable locals (probe 1).
- Probe 1 reproduces: a local named `razorpay_secret` and a local dict `body` carrying `password`/`totp` are both in the captured envelope under exactly the options `init_sentry` passes.
- SDK `_wsgi_common.py:94,110` — `attach_request_body` defaults to `True` when `data_collection` is not user-provided, and `DjangoRequestExtractor.parsed_body` returns `request.data` (DRF's parsed body). So a 500 during checkout/registration attaches the submitted body; `scrub_request` (`scrubber.py:123-131`) only filters top-level keys, and `scrubbers.recursive` is `False` (probe 2), so `{"user": {"password": ...}}`-shaped bodies are not filtered at all.
- Headers are safe in 2.71.0 (`_wsgi_common.py:242-258` strips `Authorization`/`Cookie`/`X-Api-Key` when `send_default_pii` is falsy) — so the *header* half of the docstring's claim does hold; the body/locals half does not.

**Impact.** Credential and customer-PII exfiltration to a third-party ingest on any 500, from a module whose docstring is the record that says it is prevented. Fix belongs in `common/sentry.py` (`include_local_variables=False`, `max_request_body_size="never"`, and a real recursive scrub composed in front of the existing quota guard) — one place, since `init_sentry` is the only `sentry_sdk.init` call.
