| Write-permission / capability class: absolute expectations, or recomputed from the map? | **Absolute, and deliberately so** — `test_writes_follow_the_role_map` (1511–1527) hardcodes `if role in (ROLE_CATALOGUE, ROLE_ADMIN)`, it does not import `CAPABILITY_ROLES['products.write']`, so widening or narrowing `roles.py` fails the test instead of silently moving the expectation with it (the exact anti-pattern `SlugGenerationTests` warns about at 300–303). ## Notable *good* practices (recorded so a future cycle does not "fix" them)

- **Engine differences are named, not papered over.** `SlugGenerationTests` splits the bound pins into
  generator-level (in-memory) and stored-row variants with an explicit reason (316–330, 357–379), and
  `test_slug_stays_satisfied_by_its_unique_constraint` uses `redundant_covering_indexes` rather than
  asserting "every covering index is unique", which is false on PostgreSQL's `varchar_pattern_ops` index
  (`common/testing.py`, `tests.py:1720-1740`).
- **Expectations are hand-written literals, never recomputed from the guarded constant** — the file says
  so at 300–303 and 370–374 and then actually does it ("12" × 50, "w" × 97 + "-12", 98 + "-2"). Q23-07/08/09
  are the three places the doctrine slipped.
- `test_admin_family_paths_reach_the_one_adjustment_view` (955–977) pins the mount consolidation
  structurally — `resolve()` identity for four paths plus exactly one registration in `v1_admin_patterns` —
  instead of asserting the same 201 four times.
- `test_non_slug_integrity_error_propagates` (472–489) exercises the *rejection* branch of the retry loop
  by patching `Model.save` (the immediate base), so `products.save`'s own `if "slug" not in str(exc): raise`
  is what answers. That is the correct mocking seam: the subject is still the code under test.
- `InventoryAdjustApiTests` uses `force_authenticate` on a *role-shaped* fixture built from the real
  `STAFF_ROLES`/group names and asserts the least-privilege split both ways (845–858 catalogue denied,
  859–862 inventory allowed) with the DB re-read (`stock == 10`, zero movements) after each refusal.
- `test_invalid_ordering_values_ignored_not_500` includes `"-; DROP"` and `"price,name"` — the two shapes
  that would 500 or leak a related field if the ordering param were interpolated or whitelisted loosely.

## Minor notes (not table rows)

- `ProductListFilterTests.setUp` assigns `self.staff` (61) that no test in the class uses — dead fixture.
- `ProductWritePermissionTests`' docstring ("create/update/delete require staff", 572) and
  `ProductStockEditLedgerGuardTests`' fixtures are pre-SPEC-6-03c: `make_staff()` now silently grants
  `ROLE_ADMIN` (`common/testing.py:make_staff`), so these classes actually prove "admin-role staff can
  write". They fail correctly if the group grant disappears, so this is naming drift, not a defect.
- `SlugGenerationRaceTests` subclasses a bare `TransactionTestCase` rather than an `ApiSettings`-decorated
  base, so it runs without the locmem email backend / `MEDIA_ROOT` override / MD5 hasher. Harmless today
  (no image or mail in the test) but it is the one class in the file outside the harness; adding mail to a
  restock assertion there later would hit the real backend.
- Every assertion in 59–2090 reads `res.data` (the pre-render dict), never `res.content`. `res.data` is the
  same object DRF renders, so this is not a correctness hole; the single wire-level pin is
  `test_serializer_field_set_is_pinned` (702–716). Acceptable for this file, but it is what lets Q23-01's
  malformed admin POST (an HTML surface, where `res.data` does not exist and the test falls back to
  `assertContains`) go unnoticed.
- `test_f12_default_listing_order_is_deterministic` (255–273) compares the response's ids with
  `sorted(ids, reverse=True)` **of the same response**, and issues one request; the docstring's "pages are
  stable across identical requests" is not what is measured. It is a weak-but-real descending-order pin.
