## Severity ladder (fix triage key — same words as the repo ledger)

| Sev | Label | Definition (audit-cycle-protocol Rule 7) | Fix route |
|---|---|---|---|
| **P0** | GATE-INTEGRITY | a verdict can be produced without measurement; every downstream verdict is unverifiable | **STOP-SHIP** |
| **P1** | CRITICAL | money, auth, or data integrity is wrong; cross-tenant/user data leak | blocks promotion — FIX-NOW |
| **P2** | HIGH | real functional or security defect, blast radius reaches users or money | NEXT-BUILD |
| **P2** | MEDIUM | real defect, bounded blast radius, no money/auth impact | NEXT-BUILD |
| **P3** | LOW | prose, figure, naming, dead code, hygiene, weak test assertions | FOLD-INTO-NEXT (never gets its own cycle) |
| **P4** | INFO | architecture observation, no defect | recorded only |

`Class` column = cycle-cost-triage: **CODE** (behaviour/500/wrong value/missing lock), **DOC-ONLY** (quoted name/count/citation), **INFRA** (gate or harness unsound).
`Status` = **CONFIRMED** (orchestrator re-read the cited lines and reproduced the claim) · **UNVERIFIED** (agent-read only — a hypothesis with a line reference) · ALREADY-TRACKED (with F-/V- ref) · UNREPRODUCIBLE · REJECTED · DUPLICATE (merged; see appendix).
A finding is a hypothesis until reproduced (`audit-cycle-protocol` Rule 5.3) — the `Status` column is that judgement, not the severity.
